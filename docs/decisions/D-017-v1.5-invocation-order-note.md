# D-017 — Preserve the v1.5 invocation-order note without silently reconciling it

**Status:** Unresolved source-order question; display-level handling accepted  
**Date:** 2026-10-18

## Observation

The v1.5 summary lifecycle lists the stages as:

**well-formed → semantically validated → externally authorised → execution contract accepted → attempted → observed → outcome verified**

Its worked abstract example instead describes declaring and checking the execution contract before obtaining an external authority decision. These passages describe related but not identical levels of detail, and the source does not explicitly reconcile their relative ordering.

## Decision

Do not silently rewrite either passage and do not assert a single merged total order. The gate-sequence explorer will show the v1.2 validation sequence and v1.5 summary lifecycle separately, then expose this order note beside the v1.5 source link. The discrepancy is an audit question, not permission to invent or promote a new canonical sequence.

## Options considered

1. **Rewrite the v1.5 summary to match the worked example — deferred.** This changes locked design canon without a reviewed source decision.
2. **Rewrite the worked example to match the summary — deferred.** This also changes canon without a reviewed decision.
3. **Preserve both passages and mark their relationship unresolved — accepted.** Readers see the evidence and are not given a false certainty.

## Consequences

- No historical grammar or spoken token is changed.
- The v1.2 nine-stage sequence and v1.5 seven-stage lifecycle remain separately displayed.
- A later canon revision must state whether the chain is a strict total order, a summary of milestones, or a partial order, and add positive/negative fixtures before changing either passage.
- The explorer is explanatory UI only; it does not report live gate status or execute an incantation.
